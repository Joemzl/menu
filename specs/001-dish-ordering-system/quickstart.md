# Quickstart Validation Guide: 点菜小程序

**Feature**: 001-dish-ordering-system
**Date**: 2026-06-15

## Prerequisites

- 微信开发者工具（[下载](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)）
- 已注册微信小程序 AppID
- 已开通微信云开发环境（CloudBase）
- Node.js 18.x（用于云函数本地调试）

## Setup

```bash
# 1. 克隆仓库
git clone <repo-url> menu-order
cd menu-order

# 2. 打开微信开发者工具
# 导入项目 → 选择 miniprogram/ 目录 → 填入 AppID

# 3. 初始化云开发环境
# 工具内: 云开发 → 设置 → 创建环境（如 menu-order-dev）

# 4. 创建数据库集合
# 工具内: 云开发 → 数据库 → 新建集合
#   - menus
#   - dishes
#   - orders
#   - users
#   - transactions

# 5. 部署云函数
# 右键 cloudfunctions/ 下每个函数文件夹 → 上传并部署

# 6. 配置定时触发器
# 云开发 → 云函数 → schedule → 触发器 → 新建
# Cron: 0 0 1 * * * *
```

## Validation Scenarios

### VS-1: 菜品管理流程 (User Story 1)

**Steps**:
1. 使用微信扫码登录开发者工具模拟器
2. 厨师端 → 创建新菜单"测试聚餐"
3. 添加菜品：
   - "豆浆" | 50 H币 | 早餐 | 上传图标
   - "牛排" | 300 H币 | 晚餐 | 上传图标
   - "薯片" | 80 H币 | 零食 | 上传图标
   - "可乐" | 30 H币 | 饮品 | 上传图标
4. 切换左侧分类栏，确认各分类下菜品正确显示

**Expected**:
- ✅ 4道菜品出现在对应分类下
- ✅ 切换分类栏，菜品列表随之切换
- ✅ 每个菜品卡片展示图标、名称、价格

### VS-2: 点菜 + 购物车 + H币支付 (User Story 2)

**Steps**:
1. 点菜端用户（另一个微信号/模拟器）通过分享链接进入菜单
2. 点击豆浆 + 号 2次（数量=2），点击可乐 + 号 1次
3. 打开购物车，确认总量=3，总价=130 H币
4. 点击豆浆 - 号 1次，购物车更新为数量=1，总价=80 H币
5. 点击"下单"按钮

**Expected**:
- ✅ 加减号实时更新数量和总价
- ✅ 下单后 H币余额从 10,000 变为 9,950（扣款50+30=80？不，订单详情看具体菜品... 50(豆浆)+30(可乐)=80 H币）
- ✅ 购物车清空
- ✅ 接收成功提示

### VS-3: H币不足拒绝下单 (User Story 2 — Edge Case)

**Steps**:
1. 在云数据库将测试用户 `coinBalance` 改为 50
2. 返回小程序，添加总价 100 H币的菜品
3. 点击"下单"

**Expected**:
- ✅ 提示"H币不足，请调整菜品数量"
- ✅ 订单未创建
- ✅ 余额未扣款

### VS-4: 厨师接单 + 完成 (User Story 3)

**Steps**:
1. 点菜端提交一份订单
2. 厨师端打开订单消息列表，看到新订单
3. 点击订单 → 点击"接单"按钮
4. 点菜端查看历史订单 → 状态变为"已接单"
5. 厨师端点击"完成"按钮
6. 点菜端查看历史订单 → 状态变为"已完成"

**Expected**:
- ✅ 新订单出现在厨师消息列表顶部
- ✅ 状态变更在 3s 内同步到点菜端
- ✅ 接单后按钮变为"完成"，完成后按钮消失

### VS-5: 订单历史 (User Story 4)

**Steps**:
1. 点菜端提交3份订单
2. 厨师端分别接单1份、完成1份、暂不处理1份
3. 点菜端进入历史订单页面

**Expected**:
- ✅ 3条记录分别显示"已下单""已接单""已完成"状态
- ✅ 厨师端按"已完成"筛选只显示1条

### VS-6: 评分与奖励 (User Story 5)

**Steps**:
1. 确保有一份"已完成"未评分订单
2. 点菜端进入该订单详情 → 评5星 → 提交
3. 查看 H币余额

**Expected**:
- ✅ H币余额增加 200
- ✅ 评分入口消失，显示"已评分"
- ✅ 对另一份订单评2星，余额不变

### VS-7: 订单取消与退款 (FR-019, FR-021)

**Steps**:
1. 点菜端下单一份订单（状态=已下单）
2. 进入订单详情 → 点击"取消订单"
3. 点菜端尝试取消一份状态=已接单的订单

**Expected**:
- ✅ 已下单订单取消成功，H币余额恢复
- ✅ 订单状态变为"已取消"
- ✅ 已接单的订单无"取消"按钮

### VS-8: 密码保护菜单 (FR-006)

**Steps**:
1. 厨师创建菜单并设置密码"8888"
2. 分享给点菜端
3. 点菜端进入 → 弹出密码框 → 输入错误密码"1234" 3次

**Expected**:
- ✅ 错误提示"密码错误，剩余X次"
- ✅ 第3次错误后锁定30秒，提示稍后再试
- ✅ 输入正确密码后正常进入菜单

### VS-9: 菜单过期 (FR-005)

**Steps**:
1. 厨师创建菜单，截止时间设为"当前时间+5分钟"
2. 5分钟后点菜端重新进入该菜单

**Expected**:
- ✅ 菜单显示"菜单已结束"
- ✅ ±按钮禁用，下单按钮不可点击
- ✅ 仍可查看菜品列表

### VS-10: 厨师H币入账 (FR-015, SC-009)

**Steps**:
1. 记录厨师当前H币余额（如0）
2. 点菜端下单一份总价200H币的订单
3. 厨师接单 → 完成
4. 查看厨师H币余额

**Expected**:
- ✅ 厨师余额增加200（收到订单收入）
- ✅ 点菜端已被扣款200
- ✅ 两条流水记录：点菜端支出 + 厨师端收入

### VS-11: 并发点菜 (SC-007)

**Steps**:
1. 准备3个测试账号
2. 3人同时进入同一菜单
3. 3人同时加菜并几乎同时点击"下单"

**Expected**:
- ✅ 3份订单全部成功创建
- ✅ 每个用户H币余额正确扣款
- ✅ 厨师端按时间倒序显示3条新订单
- ✅ 无数据错乱、无重复扣款

### VS-12: 微信分享 (I. 微信生态优先)

**Steps**:
1. 厨师端点击分享按钮
2. 选择发送给微信好友
3. 好友点击分享卡片

**Expected**:
- ✅ 分享卡片包含菜单名称
- ✅ 好友直接打开小程序并进入该菜单点菜页面
- ✅ 无需额外登录步骤

## Test Data Reset

测试完成后在云开发控制台执行：

```
// 清空测试数据
db.collection('orders').where({ menuId: 'test_menu' }).remove()
db.collection('transactions').where({ userId: 'test_user' }).remove()
// 重置测试用户余额
db.collection('users').doc('test_user').update({ data: { coinBalance: 10000 } })
```
